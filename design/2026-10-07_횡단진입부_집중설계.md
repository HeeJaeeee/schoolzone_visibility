# 횡단 진입부 주변 지속 차량 관측: 다음 설계

작성일: 2026-10-07. 상태: 설계 완료, 제품 구현과 재학습은 미실행.

## 1. 목표와 범위

사용자는 Message와 Intention을 최우선으로 평가하며, 기존 고정 영상·실제 사진을 이용한 실행 시연과 5분 이내 PPT를 제출한다. 이번 설계의 목표는 횡단 진입부 주변의 지속 차량 관측을 설명 가능한 현장점검 자료로 만드는 것이다.

한 가지 문제에 집중한다. 차량의 존재 자체만으로 점검 후보가 되지 않도록, 보행자가 횡단을 시작하는 위치와 차량이 대기하는 위치를 구분하고 관측한 구간의 근거를 보존한다. 움직이는 차량과 보행자의 순간 관계는 현재 조건의 한계를 설명하는 대조 자료로만 사용한다. 별도의 충돌 예측·돌발행동 탐지 기능을 추가하지 않는다.

서비스의 사용자는 보호구역 실태조사 담당 부서 또는 조사 수행기관을 가정한다. 자료는 원본 시각과 근거 사진을 확인한 뒤 현장점검할 장소·장면을 고르는 데 사용한다. 기관의 실제 구매 의향, 업무 시간 절감, 사고 감소는 검증해야 할 가설이다.

## 2. PPT에 반드시 들어갈 여섯 내용

### ① 주제를 선택한 동기: 어떤 장면에서 문제를 발견했나

AI-Hub 영상을 검토하면서 횡단보도 가까이에 큰 차량이 계속 있는 장면을 확인했다. 동시에 다른 영상에는 차량이 횡단보도를 잠깐 통과하거나 정지했다가 움직이는 장면도 있었다. 차량이 있다는 사실만으로 이 상황들을 같은 의미로 처리하면 현장점검에 도움이 되지 않는다. 따라서 보행자가 횡단을 시작하는 공간과 차량의 위치 관계를 구분해 기록하는 문제를 선택했다.

동기는 자료에서 실제로 관찰한 차이에 근거한다. 모든 CCTV가 방치돼 있다거나 모든 조사를 사고 후에만 한다고 주장하지 않는다. 어린이의 키나 실제 시야를 영상 박스만으로 측정했다고 말하지 않는다.

### ② 시스템을 만든 이유: 무엇을 사용자에게 제공하려는가

담당자가 원본 영상을 다시 찾고 현장을 확인할 수 있도록, 진입부 주변의 차량 관측을 시각·위치·근거 사진과 함께 정리하려고 만들었다. 한 장의 사진에서는 구역과 차량의 위치 관계를 확인하고, 영상에서는 같은 위치에서 이어서 관측된 구간을 기록한다. 최종 산출물은 점검할 근거 자료다.

구매를 제안할 업무는 이미 촬영된 영상의 특정 장소 점검 자료 작성이다. 새 카메라를 모든 횡단보도에 설치해야만 작동하는 사업으로 설계하지 않는다. 적합한 기존 영상이 없는 장소에는 바로 적용할 수 없다.

### ③ 시스템의 특징: 목적을 구현하는 기능은 무엇인가

사용자가 카메라별로 횡단 진입부 주변과 차량 대기 차로를 지정하고 지정 이유를 남긴다. 실제 학습한 모델이 차량의 위치를 찾으며, 프로그램이 구역 관계와 연속 관측 범위를 계산한다. 대기 차로에서만 관측된 차량은 별도 항목으로 기록하고, 두 구역의 경계와 함께 겹친 차량은 자동 제외하지 않고 검토 필요로 남긴다. 사진 결과와 영상의 시간 결과를 구분하며 원본 시각을 보존한다.

사람 탐지는 화면에서 위치를 보여주는 보조 정보로 유지한다. 사람 검출을 후보의 필수 조건으로 사용하지 않는다. 가려져 있거나 검출되지 않은 보행자 때문에 차량 후보까지 없어지는 구조를 피한다. 사람의 부재를 안전으로 해석하지 않는다.

### ④ 사용할 때 기존과 달라지는 점: 어떤 작업이 바뀌는가

원본 영상을 직접 확인하는 방식에서는 담당자가 관심 장소를 찾고, 차량이 어떤 위치에 있었는지와 관측 시간을 따로 정리해야 한다. 이 시스템을 사용하면 지정한 진입부의 후보 구간과 원본 시각, 근거 사진을 함께 열람할 수 있다. 차량 대기 차로의 관측을 별도로 표시하므로 장시간 관측됐다는 이유만으로 동일한 점검 목록에 합치지 않는다.

이는 제안하는 업무 방식의 차이다. 기존의 모든 기관이 수동으로만 처리한다거나 기존 서비스에 비슷한 기능이 없다고 주장하지 않는다. 실제 시간 절감률은 같은 영상에 대한 수동 검토와 비교한 뒤에만 제시한다. 프로그램은 무위험 판정이나 시설 변경의 최종 결정을 대신하지 않는다.

### ⑤ Message: 무엇을 중요하게 보자는 것인가

**사고 전에, 아이가 길에 들어서는 공간을 점검한다.**

관심의 중심은 자동차의 대수나 번호판이 아니라 보행자가 횡단을 시작하는 공간이다. 보행자가 그 순간 영상에서 검출되지 않아도 주변 상태를 점검할 자료를 남길 수 있다는 의미다. 실제로 아이가 보이지 않았던 시간을 측정했다거나 사고를 줄였다는 성과 문구로 바꾸지 않는다.

### ⑥ Intention: 그 의미를 위해 무엇을 의도적으로 선택했나

**기존 영상에서 횡단 진입부 주변의 지속 차량 관측을 추려, 담당자가 확인할 장면과 위치를 남긴다.**

탐지 대상은 사람·차량이지만, 기록의 중심은 사전에 지정한 진입부 주변이다. 모든 차량을 경고하지 않고 대기 차로 관측을 구분하며, 사진의 순간 겹침을 장기 지속으로 해석하지 않는다. 장면과 구역을 선정한 이유를 결과와 함께 보존하고 실제 시야·시설 조치는 현장에서 확인한다. 이 선택들이 Intention의 구현 근거다.

## 3. 구역 설계와 신호대기 처리

기존 사진 드래그 흐름을 재사용해 구역 두 개를 지정한다. 이번에는 다각형 편집기·지도·신호등 탐지 모델을 추가하지 않는다. 사각형으로 의도를 표현하기 어려운 구도는 보류한다.

- 진입부 주변 구역: 보도에서 횡단을 시작하는 연결부와 그 앞을 점검하기 위해 지정한다. 이름은 `점검 관심구역`이다. 실제 안전 또는 시야가 검증된 구역이라고 부르지 않는다.
- 대기 차로 구역: 차량이 대기하는 차로의 화면상 구간을 별도로 지정한다. 보도 연결부 자체를 포함시켜 지워버리는 용도로 사용하지 않는다.
- 각 구역의 이유, 카메라·촬영 방향·원본 해상도·기준 사진을 저장한다. 구도가 바뀌면 재지정한다.
- 구역은 결과 수치를 최대화하려고 차량 박스에 맞춰 설정하지 않는다. 도로 구조를 먼저 설명하고 지정한 좌표로 결과를 확인한다.

차량 박스와 각각의 구역의 교차 면적을 각 구역 면적으로 나눈다. 기존 10%는 초기 개발 조건으로 유지하되 최적 안전 기준으로 설명하지 않는다. 신호 상태는 판단하지 않는다.

| 진입부 주변과 겹침 | 대기 차로와 겹침 | 관측 분류 |
|---|---|---|
| 있음 | 없음 | 진입부 주변 관측 후보 |
| 없음 | 있음 | 대기 차로 관측. 진입부 후보 목록과 별도 저장 |
| 있음 | 있음 | 구역 경계 중첩. 자동 제외하지 않고 검토 필요로 별도 기록 |
| 없음 | 없음 | 지정 구역 밖 차량 |

대기 차로 구역은 정상 신호대기의 정답이 아니다. 차량의 합법성·정차 이유는 확정하지 않는다. 보호구역과 함께 겹치면 오탐이라고 자동 삭제하지 않는다. 대기 차로를 확인할 수 없거나 설정하지 않았다면 `대기 차로 구분 미설정`을 표시한다. 이 경우 정상 신호대기를 구분했다고 발표하지 않는다.

## 4. 시간 관측과 출력

기존 모델 confidence .25와 1초 표본, 관측 연결 IoU .30, 처음 박스 IoU .65, 정규화 중심 이동 .02, 최소 범위5초를 초기 개발 조건으로 사용한다. 탐지 누락과 1.1초 초과 표본 간격은 구간을 끊는다. 임의로 누락 시간을 메우지 않는다.

차량 관측을 이어 붙이는 동안 위 구역 분류가 바뀌면 구간을 나눈다. 진입부 후보·대기 차로·경계 중첩 각각의 연속 관측 결과를 별도로 보존한다. 여러 유형을 한 지속 비율로 합쳐 실제 위험 순위를 만들지 않는다.

사진 출력: 탐지 차량 수, 구역별 차량 관측, 지정 이유, 근거 사진. 지속시간은 비워둔다.

영상 출력: 원본 첫/마지막 관측 시각, 관측 범위, 해당 구간의 표본 수, 구역 분류, 근거 사진. 첫 관측부터 조건이 성립했는지와 사후 집계를 구분해 표시한다. 0~29초 표본30개는 29초 범위다.

목록은 장소와 원본 사건별로 묶어 열람한다. 현재 30초 사례의 지속 표본 비율을 학교 위험 순위로 정렬하는 표현은 제거한다. 같은 사건 A/B는 두 관측시점으로 표시한다.

## 5. 영상 선정과 학습 설계

35개 전체를 학습하는 계획이 아니다. 전체 검토는 선정·제외 근거를 얻기 위한 것이고, 학습은 별도로 선정한 실제 이미지·제공 객체 위치 라벨을 사용한다. 구역은 프로그램의 설정이며 YOLO의 안전 의미 학습 라벨이 아니다.

### 발표·시연 역할

- 핵심: 2020_11_13_18_30_suddenlyappear_night_A/B_11. 횡단보도 주변 대형차 지속 관측. A/B는 같은 사건1개다. 현재 v2의 A 학습/B 개발 이력을 숨기지 않는다.
- 대조: 2020_11_10_20_05_suddenlyappear_night_A/B_10. 정지 후 진행을 보여주되 정상 신호대기·합법성의 확정 정답으로 쓰지 않는다. 구역별 별도 관측을 시험한다.
- 통과 대조: 2020_11_09_20_22_suddenlyappear_night_A/B_10. 이동 차량이 횡단 공간을 지나가는 경우. 지속 후보0을 안전이라고 설명하지 않는다.
- 별도 사건 확인: 2020_11_12_12_30_suddenlyappear_sun_A/B_2. 현재 v2의 학습 제외 사건. 이번 상세 검토를 이용해 다음 규칙을 수정한 뒤에는 완전한 블라인드 시험이라고 부르지 않는다.
- 학습 다양성 검토만: 2020_11_12_12_53_suddenlyappear_sun_A/B_3의 큰 차량. 표시된 횡단보도가 없으므로 발표 핵심 성공 사례로 넣지 않는다.

### 다음 모델의 자료 후보

새 학습 자료 후보는 6개 사건/12개 시점이다: 2020_11_10_14_56, 2020_11_10_15_48, 2020_11_12_11_59, 2020_11_12_12_53, 2020_11_13_15_30, 2020_11_09_20_22. 큰 차량과 이동 차량, 야간·주간, 원거리·근거리 위치를 학습할 대표로 선택한다. 차량 모양 학습의 다양성을 위한 선택이며 위험행동을 모두 서비스 범위에 넣는 것이 아니다.

개발 후보는 2020_11_10_19_32, 2020_11_10_20_05, 2020_11_16_12_55의 3개 사건/6개 시점이다. 지속 조건과 대기 차로 구분을 개발 단계에서 확인한다.

학습 제외 재현 후보는 2020_11_13_18_30, 2020_11_10_12_02, 2020_11_12_12_30의 3개 사건/6개 시점이다. 새 모델의 학습에는 A/B 모두 넣지 않는다. 이 자료들은 이미 프로젝트에서 열람했으므로 `선정한 학습 제외 사건의 재현 결과`라고 보고한다. 새 장소 일반화나 최초 블라인드 평가라고 말하지 않는다.

나머지 11개 영상은 이번 후보 구성에서 제외한다. 자료 후보는 `선정자료_후보.json`에 전체 경로와 역할을 기록한다. 실제 원본과 2fps 대응 XML60개/영상의 존재를 확인하고 기존 학습 폴더·모델을 변경하지 않는다.

재학습은 기존 v2 가중치를 이어 쓰지 않고 원래의 사전학습 모델에서 시작해야 한다. 주요 핵심 사건을 이번 모델 학습에서 제외한 이력이 명확해야 하기 때문이다. 이미지1,260장·5epoch 등 기존 PPT 숫자는 새 학습 완료 시 실제 기록으로 바꾼다. 설계 문서의 자료 후보를 이미 학습한 것처럼 쓰지 않는다.

## 6. 검증 기준

1. 구역 밖 차량은 진입부 후보가 되지 않고, 대기 차로에서만 머무는 차량은 대기 차로 관측으로 남는다.
2. 두 구역과 겹치면 자동 제외하지 않고 경계 중첩으로 기록한다. 정상·불법·안전이라고 단정하지 않는다.
3. 같은 위치에서 0~5초 여섯 관측이면 범위5초, 0~4초 다섯 관측이면 범위4초다. 시간·표본을 혼동하지 않는다.
4. 누락 또는 유형 변경이 있으면 구간을 나누고, 실제 관측되지 않은 시간을 보충하지 않는다.
5. 핵심 야간 A/B와 정지 후 진행·통과 대조는 원본, 제공 XML의 동일 규칙, 모델 결과를 나란히 기록한다. 모델 박스가 흔들린 경우를 성공처럼 숨기지 않는다.
6. 두 구역이 분리되지 않는 구도는 보류한다. 실제 영상에 없는 신호대기 정답을 임의로 만들지 않는다. 재현 가능한 구역 구분 대조가 확보되지 않으면 `신호대기 문제 해결 완료`라고 발표하지 않는다.
7. 사진에서 지속시간·안전 판정을 출력하지 않는다. 사람 미검출을 후보 제외 또는 안전으로 사용하지 않는다.
8. 학습/개발/학습 제외 사건 ID가 서로 겹치지 않는다. 모든 A/B를 함께 배치한다. 새 모델이 기존 핵심 사건의 학습 가중치를 이어받지 않는다.
9. 지역별 사고 위험 또는 실제 시야 차단시간은 검증 범위 밖이다. 목적 검증은 관측 분류와 근거 기록이 설명한 대로 작동하는지로 판단한다.

## 7. 기존 코드에서 필요한 변경과 순서

이번 설계는 기존 사진 분석·구역 설정·영상 관측·근거 저장 흐름에 한정한다. 새 프레임워크나 별도 대시보드를 만들지 않는다.

1. `photo_analysis.py`의 한 구역 판정을 두 구역 관계 판정으로 보완한다. 판정 의미와 사진 출력부터 검증한다.
2. `temporal.py`와 `video_analysis.py`가 구역 분류별 관측 구간과 근거를 저장하도록 보완한다. 총합 위험 순위 표현을 제거한다.
3. `app.py`와 `video_window.py`의 기존 구역 지정·설정 저장을 재사용하고 지정 이유·구분 미설정·경계 중첩을 표시한다. 사진 시연을 우선한다.
4. 실제 장면에 맞는 두 구역을 선정 영상에서 시험한다. 분리 가능 여부와 지정 이유를 먼저 확인한 뒤 학습 자료 후보를 확정한다.
5. 필요 자료를 별도 폴더로 구성해 새 모델을 학습·평가한다. 기존 결과와 비교해 조건에 맞는 모델을 선택하고 실제 앱에서 재실행한다.
6. 기능·원본 재현·자료 사용 이력이 통과한 뒤에만 최종 PPT를 갱신한다.

이 문서 작성 시 제품 코드·모델·PPT는 수정하지 않았다. 사용자의 요청은 다음 설계 진행이며 설계 결과를 먼저 검토할 수 있게 한다.
